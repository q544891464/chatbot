# 主链路错误对照表

## 文档说明
本表仅覆盖当前主链路：

- H5 前端：`h5-chatbot`
- Node 代理与会话存储：`server`

不覆盖 `dify-智能助手` 原型项目。

阅读建议：

- 先按“前端用户可见错误”定位页面提示
- 再按“后端接口错误”定位具体接口
- 最后结合“上游来源归类”和“常见定位建议”缩小问题范围

## 前端用户可见错误

### 会话加载/同步
| 错误场景 | 触发入口 | 典型提示文案 | 实际来源 | 优先检查项 | 处理建议 |
| --- | --- | --- | --- | --- | --- |
| 首次加载会话失败 | 页面启动后 `initConversations()` | `会话存储不可用，当前切换为本地临时模式：...` | `/api/conversations` 读取失败 | 代理服务是否启动、Base URL 是否正确、MySQL 是否可连 | 先访问 `/api/health`，再检查 MySQL 与 `userId` |
| 会话同步失败 | 本地保存会话时 `saveConversations()` | `会话同步失败：...` | `/api/conversations/sync` 写入失败 | 请求体中的 `userId`、数据库字段/表结构、MySQL 权限 | 优先查看返回里的 HTTP 状态码与错误明细 |
| 降级到本地临时模式 | 会话读取异常后自动回退 | `会话存储不可用，当前切换为本地临时模式：...` | 服务端不可达或数据库异常 | 代理服务、数据库连接、CORS | 仅表示服务端存储失败，不影响纯前端临时使用 |

## 上游来源归类
| 来源标识 | 含义 | 常见出现位置 | 优先排查 |
| --- | --- | --- | --- |
| `server-config` | 本地代理缺少必要环境变量 | 线程创建、聊天、认证、反馈 | `server/.env` |
| `alt-auth` | ChatbotAgent 上游认证失败 | `/api/alt-thread`、`/api/alt-chat*`、`/api/feedback` | `ALT_AUTH_URL`、用户名密码、token 有效期 |
| 聊天上游 | ChatbotAgent 聊天接口返回错误 | `/api/alt-chat`、`/api/alt-chat-stream` | `ALT_API_URL`、请求体、上游服务状态 |
| 线程上游 | ChatbotAgent 线程接口返回错误 | `/api/alt-thread` | `ALT_THREAD_URL`、线程创建参数 |
| OAuth Token 接口 | OAuth 换 token 失败 | `/api/auth-token` | `code`、`redirectUri`、客户端密钥 |
| OAuth UserInfo 接口 | OAuth 查询用户信息失败 | `/api/auth-userinfo` | access token、权限范围、上游服务 |
| 反馈上游 | 反馈提交失败 | `/api/feedback` | `FEEDBACK_BASE_URL`、messageId、上游权限 |

## 常见定位建议

### 本地配置问题
- 检查 [server/.env](/d:/Code/chatbot/server/.env) 是否存在且关键变量齐全
- 重点变量：`ALT_API_URL`、`ALT_THREAD_URL`、`ALT_AUTH_URL`、`FEEDBACK_BASE_URL`、`AUTH_SERVER_DOMAIN`
- 页面若不是从 `8787` 打开，确认 `API Base URL` 是否为 `http://127.0.0.1:8787/api`

### MySQL 问题
- 先确认 MySQL 已启动且 `DB_HOST`、`DB_PORT`、`DB_USER`、`DB_PASSWORD` 正确
- 旧库重点检查 `messages.external_message_id` 字段是否存在
- 若返回“表不存在”，执行最新初始化 SQL

### 代理服务问题
- 访问 `http://127.0.0.1:8787/api/health`
- 若健康检查失败，优先确认本地 Node 服务是否启动
- 若页面能打开但接口不通，重点检查 Base URL 和浏览器控制台

### 上游认证问题
- 单独验证 `ALT_AUTH_URL` 是否可访问
- 检查用户名密码、client_id、client_secret 是否过期或被修改
- 若错误只出现在聊天/反馈而不是会话存储，优先看这一层

### 上游聊天服务问题
- 能创建线程但不能聊天，优先看 `ALT_API_URL`
- 聊天接口报 4xx 时先核对 thread_id、query 和权限
- 聊天接口报 5xx 时优先查看上游服务日志

### 浏览器网络 / CORS 问题
- 优先直接打开 `http://127.0.0.1:8787/`
- 若从文件、本地其他端口或反向代理地址打开页面，可能会出现跨域或错误主机请求
- 浏览器出现 `Failed to fetch` 时，先看网络面板，再看控制台中的 CORS 报错
